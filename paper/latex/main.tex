\begin{abstract}
We study when zero-shot time-series foundation models improve short-term
retail demand forecasts relative to conventional baselines.  The paper is
framed as a benchmark study supported by a structured literature search, not
as a confirmatory pooled meta-analysis.  The literature search establishes a
gap: published retail evaluations rarely report model families, metrics,
baselines, and workloads in a way that supports paired FM-vs-tree inference.
We therefore combine two external benchmark suites (fev-bench and GIFT-Eval)
with matched-panel local experiments on M5, Rohlik, and Favorita.
For the external suites, the primary descriptive file contains $k=498$
Source~A contrasts of
$\log(\text{FM metric}/\text{best conventional baseline metric})$.
Because the recorded series-count term
$1/n_{\text{FM}}+1/n_{\text{baseline}}$ is a workload proxy rather than a
validated sampling variance, we report suite- and metric-specific summaries:
SQL has the clearest directional FM advantage (median log-ratio $-0.229$,
FM lower in 92\% of rows), whereas \WAPE{}/ND (median $-0.047$, 66\%) and
\MASE{} (median $-0.036$, 61\%) are much closer to the best baseline.
For a concrete Source~A slice, we rerun official fev-bench retail windows for
Seasonal Naive, Chronos-Bolt-Tiny, Chronos-2, TiRex, and TimesFM~2.5, store
prediction-level outputs, and compute paired bootstrap \WAPE{} log-ratio
covariance matrices for 20 retail tasks and 179,258 paired series-window units
per FM contrast.  The local Source~B matched panel uses 100 shared top-volume
series per dataset, common rolling-origin windows, prediction-level outputs,
run ledgers, and paired bootstrap covariance matrices for Seasonal Naive,
recursive/direct LightGBM, Chronos-Bolt-Tiny, Chronos-2, Moirai~2.0-Small,
batched TiRex, and TimesFM~2.5.  In this panel, Chronos-2, Moirai, and TiRex
are lower than the best local baseline in all nine dataset--horizon point
estimates, though the baseline is intentionally fixed-budget rather than
strongly tuned.  The defensible conclusion is conditional: rankings depend on
metric, baseline strength, multi-step protocol, workload matching, and demand
characteristics.  We provide prediction-level artefacts, covariance matrices,
and a validation checklist for retail bake-offs rather than deterministic
deployment rules.
\end{abstract}

\section*{Data availability}
A historical technical-report snapshot is archived on Zenodo at
\url{https://doi.org/10.5281/zenodo.21338004}.  The live repository for the
current analysis is
\url{https://github.com/MaciejR/large-scale-demand-forecasting-benchmark};
the release package corresponding to this manuscript is prepared as a
versioned Zenodo-ready archive under \path{release/} rather than overwriting the
historical snapshot, and is published as GitHub release v1.12 at
\url{https://github.com/MaciejR/large-scale-demand-forecasting-benchmark/releases/tag/v1.12}.
The package records the source commit in
\path{COMMIT.txt} and file hashes in \path{CHECKSUMS.txt}.
The repository includes derived extraction tables, analysis code, generated
tables/figures, study-characteristics data, audit outputs, and replication
scripts, but not raw competition data or untracked fev-bench prediction
parquet trees.
The M5 dataset is publicly available via Kaggle; the Favorita
dataset is publicly available via Kaggle; the Rohlik~v2 dataset
is available at \url{https://github.com/Rohlik/rohlik-orders-forecasting-challenge}.
